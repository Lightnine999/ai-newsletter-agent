# 자료를 가져오는 길과 소스 관문

노드 2부(7~14장)를 따라 정한 내용이에요. 코드는 [graph.py](../graph.py)의 `collect`예요.

## 다섯 칸 사다리 (7장)

위 칸일수록 안전하고, 위 칸을 쓸 수 있으면 아래로 내려가지 않아요. 칸은 소스마다 골라요.

| 칸 | 예 | 이 프로젝트 |
|----|----|-------------|
| ① 공식 API | Hacker News | 지금 소스 목록엔 없어요 |
| ② RSS·Atom 피드 | 언론사·회사 블로그 | **씀** (5곳 모두) |
| ③ 공개 데이터셋 | 실시간이 아니에요 | 안 씀 |
| ④ 집계 서비스 | 선별 기준을 통제 못 해요 | 안 씀 |
| ⑤ 직접 스크래핑 | 화면이 바뀌면 깨져요 | 목록 수집엔 안 쓰고, 고른 기사 본문만 trafilatura로 뽑아요 (11장) |

## 소스 관문 세 개 (10장)

| 관문 | 질문 | 못 넘으면 |
|------|------|-----------|
| G1 본문 | 원문 주소로 갔을 때 본문이 600자 넘게 뽑히나? | 제목만 보고 요약을 지어내요 |
| G2 생존 | 최근에도 글이 올라오나? | 매일 0건인데 요청 시간만 써요 |
| G3 접근 | 자동 수집이 막히지 않나? (403, robots.txt) | 되더라도 안 써요 |

RSS 요약은 한 문장에서 한 문단이라 어느 소스든 요약 재료로는 모자라요. 그래서 기준은 RSS 요약 길이가 아니라 "원문에서 본문이 뽑히느냐"예요 (11장). report 노드도 같은 600자 기준으로 기사를 빼요.

## collect가 하는 일 (13·14장)

1. **시간으로 거르기**: 지금부터 `hours`(기본 24)시간 전보다 오래된 글과 날짜가 없는 글은 버려요.
2. **주소로 거르기**: 같은 글이 두 번 들어오지 않게 주소로 비교해요. 노드는 `?` 뒤를 통째로 뗐지만, AI타임스처럼 기사 번호가 `?` 뒤에 있는 곳이 있어서 추적용 꼬리표(`utm_*`, `fbclid`, `gclid`, `ref`)만 떼요.
3. **실패 가두기**: 소스 하나가 연결에 실패해도 나머지는 계속 모으고, 실패한 소스 이름을 로그에 남겨요.

아직 안 한 것: 403·404 응답은 예외가 안 나서 "응답 없음"에 안 잡혀요. 노드 14장대로 `.raise_for_status()`를 붙이거나 0건인 소스 이름도 로그에 남기면 잡혀요.
