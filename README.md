# AI 아침 브리핑 에이전트

매일 아침 7시 30분(KST), 그날 나온 AI 기사 중 개발팀이 알아야 할 5건을 골라 세 칸으로 요약하고 Discord로 보내는 LangGraph 에이전트예요. AIFFEL 노드 "매일 아침 AI 소식 5건을 골라 보내는 에이전트"를 1부부터 7부까지 따라 만들었어요.

```
START → collect → select ─(Send × 기사 수)→ report → verify → publish → END
                     └──────── 고른 기사가 0건이면 ────────┘
```

메인은 [graph.py](graph.py)(State·노드 다섯 개·`build()`·`run()`)와 [run.py](run.py)(실행 진입점)예요.

| 노드 | 하는 일 | State 칸 |
|------|---------|----------|
| collect | RSS 13곳 + Hacker News API + Anthropic 사이트맵, 모두 15곳에서 최근 24시간 글만 모으고, 같은 주소는 한 번만 남겨요. 응답 없는(403 포함) 소스는 건너뛰고 이름을 로그에 적어요 | `collected` |
| select | 소스별로 섞은 뒤 40건 묶음마다 8건(예선), 살아남은 것을 한 화면에 놓고 순위를 매겨 같은 사건·매체당 2건을 넘지 않게 5건(본선). AI타임스는 본선 후보에 최소 2건 올리고(발행은 경쟁), 종합 IT 피드는 합쳐 1건. 구조화된 출력으로 이유와 사건 라벨을 받아요 | `picked` |
| report | `Send`로 기사마다 워커를 띄워요. 원문 본문이 600자 미만이면 빼고, headline·summary·why 세 칸으로 요약해요 | `drafted` (이어 붙이기) |
| verify | 요약을 쓴 호출과 따로 부른 LLM이 headline·summary를 원문과 뜻으로 대조해요. 떨어진 건 버리고 출처를 로그에 남겨요 | `verified` |
| publish | Discord embed 카드로 보내요. `DRY_RUN` 기본은 1(보내지 않음), 0건이면 "오늘은 조용합니다" 한 장 | 바깥 |

소스 선택과 관문은 [docs/sources.md](docs/sources.md)에 정리했어요.

실행 로그 예시:

```
① 수집   24시간 time window · 72건
② 선별   72 → 예선 16 → 5건
   취재 제외 AI타임스 · 본문 475자
④ 검수   4 → 4건
⑤ 발행   4건 · 보냄
```

## 노드와 다르게 넣은 것

| 위치 | 바꾼 것 | 이유 |
|------|---------|------|
| `graph.py` `url_key` | 주소 비교 때 `?` 뒤를 통째로 떼지 않고 추적용 꼬리표(`utm_*`, `fbclid`, `gclid`, `ref`)만 떼요 | AI타임스 주소는 기사 번호가 `?idxno=` 뒤에 있어서 50건이 1건으로 합쳐졌어요 |
| `graph.py` `fan_report` | 고른 기사가 0건이면 `verify`로 바로 가요 | 노드 44장의 고치는 법. 0건인 날에도 "오늘은 조용합니다"가 가야 멈춤과 구분돼요 |
| `graph.py` `publish` | ⑤ 줄을 `보냄` / `dry-run` / `실패` 세 가지로 적어요 | 발송 실패가 `dry-run`으로 찍혀 헷갈렸어요 |
| `run.py` | 보내야 하는 실행인데 못 보냈으면 `exit 1`로 끝나요 | 노드 41장 ①: Discord가 거절해도 실행이 성공으로 끝나 실패 메일이 안 왔어요 |
| `graph.py` `SOURCES` 외 | 노드 13장의 5곳에서 15곳으로 늘리고, HN API와 Anthropic(사이트맵 + 글 페이지 발행일)을 더했어요. 피드 요청에 `raise_for_status()`를 붙였어요 | AI타임스가 403으로 막힌 날 72건이 20건으로 줄었어요. 8장 실습 데이터(11곳·하루 50~120건)에 맞추고, 14장대로 403도 로그에 남게 했어요 |
| `graph.py` `select` | 예선 전에 소스별로 번갈아 섞고(`interleave`), CRITERIA에 'AI와 직접 관련 없는 소식'을 버릴 것으로 넣고, 본선에서 8건 순위를 받아 event 라벨과 매체 이름을 Counter로 세요(매체당 2건) | 소스를 늘리자 한국어 종합 피드 60건이 예선 묶음 두 개를 채워 발행 5건 중 4건이 쏠리고 AI와 무관한 기사가 섞였어요. 20장의 '라벨 세기·매체 상한'을 그대로 넣었어요 |
| `graph.py` `select` (우선 소스) | AI타임스는 **본선 진출만** 보장해요. 예선에서 2건이 안 올라오면 AI타임스 기사끼리 따로 순위를 매겨 본선 후보에 넣고, 발행 자리는 본선에서 다른 기사와 똑같이 경쟁해요. 전자신문·ZDNet Korea는 합쳐서 최대 1건이에요. 본선 순위가 바닥나면 예선 통과분에서 이어서 채워요 | 소스를 늘린 뒤 국내 AI 전문지인 AI타임스가 예선 묶음 운에 밀려 아예 비교받지 못할 수 있었어요. 발행 자리까지 보장하면 더 좋은 기사를 밀어내서, 17장 '서로 비교해 고른다'에 맞게 기회만 보장해요 |
| `graph.py` `report` | 헤드라인·요약에 한글이 없으면 한국어 지시를 붙여 한 번 다시 쓰고, 그래도 영어면 버리고 로그에 남겨요 | 24장 한글 검사를 연결했어요. 영어 헤드라인이 실제로 나왔어요 |

## 로컬 실행

```bash
uv venv && uv pip install -r requirements.txt
cp .env.example .env                 # OPENAI_API_KEY, DISCORD_WEBHOOK_URL 채우기
.venv/bin/python run.py --dry-run    # 보내지 않고 로그와 보낼 카드만 출력
DRY_RUN=0 .venv/bin/python run.py    # 실제로 Discord에 보냄 (.env의 DRY_RUN=1이 기본값)
```

## 매일 아침 받아 보기 (GitHub Actions)

1. Discord 채널 편집 → 연동 → 웹후크 → 새 웹후크 → URL 복사
2. 저장소 Settings → Secrets and variables → Actions에 `OPENAI_API_KEY`, `DISCORD_WEBHOOK_URL` 등록
3. Actions 탭 → `매일 브리핑` → Run workflow에서 dry_run을 체크해 한 번 돌려 로그 확인 → 정상이면 체크를 끄고 다시 실행

스케줄은 `30 22 * * *`(UTC) = 매일 07:30 KST예요. 알아둘 점:

- GitHub cron은 늦어지거나 **아예 빠질 수 있어요**(2026-10-29 07:30 실행이 실제로 빠졌어요). 그래서 예비 스케줄 07:50, 08:10을 더 두었어요. 실제 발송 실행은 먼저 그날(KST) 성공한 '브리핑 발송' 실행이 있는지 보고, 있으면 건너뛰어요. 실행 이름을 `브리핑 발송` / `브리핑 dry-run`으로 나눠서 dry-run은 보낸 것으로 세지 않아요. `concurrency`로 한 번에 하나씩만 돌아서, 밀린 07:30 실행과 07:50 실행이 겹쳐도 두 번 보내지 않아요.
- GitHub 밖에서도 한 번 더 봐요. 맥의 launchd 잡(`com.qjc.briefing-watch`, 매일 07:30·07:40·08:10·08:40)이 오늘 발송 실행이 없으면 맥 알림을 띄우고 `gh workflow run`으로 대신 실행해요. 이 잡은 저장소가 아니라 작업하는 맥에 있어서, 맥이 꺼져 있으면 동작하지 않아요(자고 있었으면 깨어날 때 돌아요).
- 공개 저장소에 60일간 커밋이 없으면 스케줄 워크플로가 자동으로 꺼져요. Actions 탭에서 다시 켜 주세요.
- `watchdog` 워크플로(노드에는 없는 추가 장치)가 08:30에 "07:30 이후 시작하여 08:30까지 완료된 브리핑 발송이 있나"를 보고, 없으면 같은 웹훅으로 알려요. 다만 **감시 대상과 같은 GitHub 스케줄러**라서 스케줄이 통째로 빠지는 날엔 같이 빠져요(2026-10-29에 둘 다 안 돌았어요). 웹훅이 고장 난 날엔 알림도 막혀요.

## 아직 못 하는 것 (노드 44장)

- 평가셋이 없어 프롬프트를 바꾼 뒤 나빠졌는지 몰라요.
- 발행 전 사람 승인이 없어요.
- 실행 기록(소스별 건수, 단계별 탈락)이 파일로 쌓이지 않아요.
- Anthropic 글은 발행일이 날짜까지만 있어서 24시간 창이 아니라 '어제·오늘 날짜'로 걸러요.
- AI타임스 피드는 시각을 시간대 없이 한국 시간으로 적어서, UTC로 읽으면 9시간 미래 글로 보여요.

## 참고용: `newsletter/` 패키지

노드를 따라가기 전에 먼저 만들어 본 완성본이에요. 기사마다 점수 매기기, 숫자 글자 대조, 되돌아가는 검수 엣지처럼 **노드가 비교 끝에 접은 방식**이 들어 있어서 비교용으로만 남겨 뒀어요. 매일 실행에는 쓰지 않아요. 테스트는 `uv pip install pytest` 후 `.venv/bin/python -m pytest -q`로 돌려요.

### 2026-10-29 예약 누락 보완

- 발송은 GitHub Actions가 해요. 맥이 꺼져 있어도 예약은 돌아요. GitHub이 늦으면 늦게 올 뿐이에요(2026-10-30에는 07:30 예약이 11:03에 왔어요).
- 맥 감시는 보험이에요. 07:30·07:40·08:10·08:40에 오늘 실행 기록을 보고, 성공했거나 진행 중이면 아무것도 안 해요. 실행이 없거나 실패만 있을 때만 `workflow_dispatch`로 대신 실행해요. 맥이 자고 있었으면 깨어날 때 돌아요.
- 하루 한 번만 보내요. 실제 발송 실행은 예약이든 손으로든 그날(KST) 성공한 '브리핑 발송'이 있으면 건너뛰어요. 2026-10-30에 맥이 08:44에 대신 보낸 뒤 11:03 예약이 한 번 더 보낸 일이 있어서, 손으로 보낸 것도 세도록 바꿨어요. dry-run은 세지 않으니 시험은 dry-run으로 해요.
- watchdog은 "08:30까지 끝난 아침 발송"만 인정해요. 늦게 손으로 복구한 발송이 그날 아침의 누락을 가리지 않게 하려는 거예요.
